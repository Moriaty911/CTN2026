平台读取→ Perceive→ Jev 漏斗→ Guard→ Act（写入）→ State + Telemetry→ 校准 / 答辩
01设计前提稀缺性
  • 平台读取 ≈ 0.61 req/s／队 买不到
  • 平台写入仅 ~11% 请求 最稀缺
  • Jev 推理 $0.042 / 1M 充裕
  • LLM 生成 充裕（规则 5.1 允许外部模型）
  • → 把稀缺读取，换成高价值写入
02感知 Perceive读额度
  • 优先趋势 / 定向信息流 / mentions，不轮询时间线
  • 本地缓存去重，重复分析不再打平台
  • read_pressure 升高 → 自动抬高筛选门槛
  • 必须读 get_feed(citizen) ← 曝光归因的前提
  • 产出：原始内容 一律不可信
03决策 DecideJev
  • Stage A 批量粗筛：1 请求 × N 帖（内部并行）
  • Stage B 逐帖深评：~10 个正交问题
  • 问题集：相关性 / 可争取性 / 传播价值 / 风险 / 成本路由
  • 窄播定位：优先「可争取 × 我方信息流占比低」
  • 绝不问「要不要回复」这种复合问题
04内容 Content生成
  • 可信话术库：封闭语料，进 git（规则 7.5 要交源码）
  • 论点 × archetype × push_distance（接受域）
  • 40 个人设 voice spec，含 avoid_phrases
  • needs_nuance 路由 → RAG 改写 ／ LLM 生成
  • 多样性守卫：MinHash 词法相似度（非语义）
05状态 Statesqlite
  • 同步 sqlite3 + WAL（0.6 req/s 不需异步 DB）
  • exposure：哪个市民何时看到什么 不可追溯
  • targets：信息流占比 + 对照组标记
  • decisions：Jev 完整概率与置信度
  • budget 账本 · 断点续跑（2 周必崩）

06安全 Guard对手合规攻击
  • 入境隔离：注入检测必须在 LLM 之前
  • 发布前护栏：rule_risk / hate / 冒充
  • 注入四层级：T1 反驳 → T2 诱导 → T3 劫持 → T4 投毒
  • 两库物理隔离：可信库 ≠ 观测库（防 RAG 投毒）
  • 工具调用门控：被劫持的典型特征是「计划外动作」
  • ⚠ 注入 NPC 未被授权 → 落 5.3 边缘条款，须问
07执行 Act写额度
  • 双层令牌桶：团队级 + 账号级
  • 读 / 写独立桶 ← 最重要的限速决策
  • 429 → 自动降速；优先砍读取，保护写入
  • 账号池：ACTIVE / THROTTLED / SUSPENDED / RETIRED
  • 唯一写入出口 · 记账 · 结构化日志
08测量 Measure因果
  • 三种「买账」会背离：互动 ≠ 态度 ≠ 投票
  • 2025 的教训：多数队伍优化了互动，牺牲了影响力
  • 分层对照组 10–15%：牺牲覆盖率换因果估计
  • 预注册预测：唯一能证伪自己的机制
  • 五闸门：信息流 / 注意力 / 接受域 / 更新 / 保持
  • 实验反推：接受域测绘 · 剂量 · 来源 · 框架 · 渠道
09交付 Delivery运维
  • 建设顺序 1–8：阶段 1–6 与官方 API 无关
  • 阶段 8 = client/legit_v1.py，只改这一个文件
  • 部署：systemd Restart=always + deploy.sh
  • 目录切分：app/ · state/ · logs/ · .env
  • git 私有；state/logs/密钥永不入库（规则 5.2 / 5.6）
  • 降级矩阵 6 行：宁可少做，不可乱做
