01Design Premisescarcity
  • Platform reads ≈ 0.61 req/s per team cannot be bought
  • Writes are only ~11% of requests scarcest
  • Jev inference $0.042 / 1M abundant
  • LLM generation abundant (Rule 5.1 permits external models)
  • → Convert scarce reads into high-value writes
02Perceiveread quota
  • Prefer trending / targeted feeds / mentions over polling timelines
  • Local cache + dedupe; never re-hit the platform for the same content
  • read_pressure rises → triage threshold rises automatically
  • Must read get_feed(citizen) ← prerequisite for exposure attribution
  • Output: raw content, treated as untrusted
03DecideJev
  • Stage A batch triage: 1 request × N posts (evaluated in parallel)
  • Stage B per-post deep scoring: ~10 orthogonal questions
  • Question set: relevance / persuadability / reach / risk / cost routing
  • Narrowcast targeting: prefer “persuadable × low share of their feed”
  • Never ask compound questions like “should I reply?”
04Contentgeneration
  • Trusted talking-point store: closed corpus, committed to git (Rule 7.5 requires source)
  • Argument × archetype × push_distance (latitude of acceptance)
  • 40 persona voice specs, including avoid_phrases
  • needs_nuance routing → RAG rewrite vs LLM generation
  • Diversity guard: MinHash lexical similarity (not semantic)
05Statesqlite
  • Synchronous sqlite3 + WAL (no async DB needed at 0.6 req/s)
  • exposure: which citizen saw what, and when unrecoverable if unlogged
  • targets: feed share + control-group flag
  • decisions: Jev’s full probabilities and confidence
  • budget ledger · crash-resume (a 2-week run will crash)

06Guardopponents attack legally
  • Inbound quarantine: injection detection must run before the LLM
  • Pre-publish guardrail: rule_risk / hate / impersonation
  • Four tiers of injection: T1 rebuttal → T2 steering → T3 hijack → T4 poisoning
  • Physically separate stores: trusted ≠ observed (prevents RAG poisoning)
  • Tool-call gating: an “off-plan action” is the tell of a hijacked agent
  • ⚠ Injecting NPCs is not authorised → falls under the 5.3 edge clause; must ask
07Actwrite quota
  • Two-level token buckets: team + per-account
  • Independent read / write buckets ← the most important rate-limit decision
  • 429 → auto slow-down; shed reads first to protect writes
  • Account pool: ACTIVE / THROTTLED / SUSPENDED / RETIRED
  • Single write egress · accounting · structured logs
08Measurecausal
  • Three meanings of “buying in” diverge: engagement ≠ attitude ≠ vote
  • 2025’s lesson: most teams optimised engagement and sacrificed influence
  • Stratified control group 10–15%: trade coverage for a causal estimate
  • Pre-registered predictions: the only mechanism that can falsify us
  • Five gates: feed / attention / acceptance / update / persistence
  • Reverse-engineer by experiment: acceptance mapping · dose · source · framing · channel
09Deliveryops
  • Build order 1–8: phases 1–6 are independent of the official API
  • Phase 8 = client/legit_v1.py — the only file that changes
  • Deploy: systemd Restart=always + deploy.sh
  • Directory split: app/ · state/ · logs/ · .env
  • git private; state / logs / secrets never committed (Rules 5.2 / 5.6)
  • 6-row degradation matrix: better to under-act than to act recklessly
How to read this map — Left wing = input and processing (premise / perceive / decide / content / state). Right wing = assurance and output (guard / act / measure / delivery). Coloured top borders match the legend above. Within branches, red = scarcest or highest risk, amber = to be confirmed, green = abundant or favourable.
