01设计前提：两个稀缺资源，不是一个

几乎所有 bot 架构都默认「算力是瓶颈」，于是把力气花在省 token 上。这个假设在本比赛里是错的。

资源稀缺程度依据能否花钱买
平台读取额度极稀缺2025 公开数据反推：每队 ≈ 0.61 req/s（读+写合计）❌ 买不到
平台写入额度最稀缺2025 仅约 11.4% 请求为发帖（7.07M 帖 / 62M 请求）❌ 买不到
Jev 推理充裕$0.042 / 1M token，输出免费，外部 API 不吃平台限速✅ 随便买
LLM 生成充裕外部模型明文允许（规则 5.1 / 5.2）✅ 可以买
设计的全部意义 把稀缺的平台读取，转换成高价值的平台写入。
Jev 是这两者之间唯一充裕的资源 —— 所以它不是「省钱过滤器」，而是花得起钱的判断力。要用得奢侈，不是用得吝啬。

一条铁律

除了 client/ 里的适配器，任何代码不许碰平台。
除了 act.py，任何代码不许发起写动作。

这条规则一旦破了，限速保证就失效 —— 而限速失效的代价是封号。账号是消耗品，但换号要重新养。

02整体架构

三段式管线 + 两个旁路资源 + 一个权威状态。箭头标注了每一跳传递的东西，以及它是否可信。

Perceive 消耗读取额度
预算感知的感知循环
  • 优先「趋势榜 / 定向市民信息流 / mentions」，而不是全量轮询时间线
  • 本地缓存去重 —— 重复分析不再打平台
  • 读取压力升高时自动提高筛选门槛（read_pressure）
↓ 原始内容 —— 一律视为不可信数据
Decide Jev 充裕
两级 Jev 漏斗 → 动作分配
  • Stage A 批量粗筛：一次请求处理 N 帖（1 state × N 问题，内部并行）
  • Stage B 逐帖深评：仅对幸存者做 ~10 个正交判断
  • 按「买哪个分数」分派到动作阶梯，而不是按「贵不贵」
  • 窄播定位：优先「可争取且我们信息流占比低」的市民
旁路：可信话术库（封闭语料）→ 只提供论点/事实/人设，绝不接受平台内容
↓ Decision（含完整 Jev 概率与置信度）
Guard Jev 护栏
发布前合规检查 + 入境隔离
  • 草稿过 Jev：rule_risk / hate / impersonation → ALLOW / FLAG / BLOCK
  • 入境内容在进入 LLM 之前做注入检测（否则为时已晚）
  • 多样性守卫：与自家队伍近期内容相似度过高 → 重写
↓ 已批准的 Action
Act 消耗写入额度
双层令牌桶 → 执行 → 记账
  • 团队级桶 + 账号级桶，读/写完全隔离
  • 429 → 自动降速；优先砍读取，保护写入
  • 账号被封 → 池子摘除，重新分配，管线不中断
↓
State + Telemetry 本地
sqlite（同步）+ JSONL
  • 唯一权威状态：断点续跑、曝光日志、预算账本
  • 每个决策记录 Jev 完整概率 → 闭环校准的燃料
  • 同时是悉尼 7 分钟答辩的证据基础
为什么必须拆成三段 三种延迟差两个数量级：平台 100–200ms、Jev 70–500ms、LLM 生成 1–5s。单线程「读→判断→生成→发」的循环里， LLM 的 3 秒会把整条感知管线卡死 —— 而在趋势窗口里卡 3 秒就是错过窗口。 三段之间用 asyncio 队列解耦；但队列不进状态，重启时从 sqlite 重建。

04关键设计决策

① 状态用 sqlite，且是同步的

在 0.61 req/s 的负载下，异步数据库是没有收益的复杂度，纯粹是故障源。用标准库 sqlite3，WAL 模式，短事务。主流程是 async，但这个负载下阻塞几毫秒完全可接受。

表用途
accounts账号池 + 健康状态 + 养号进度
posts_seen去重 + 本地缓存（避免重复读取）
decisions每个决策 + Jev 完整概率与置信度
actions执行结果
exposure哪个市民何时看到我们的什么 ← 不可追溯，Day 1 必须有
targets目标市民 + 信息流占比估计 + 对照组标记
budget请求账本（重启后继续计数）

断点续跑不是加分项，是必需项 —— 两周不间断运行，进程一定会崩。

② 账号池是消耗品，且要提前养

平台规则 LS.5.1：限速 “varies by trust signals and recent activity”。所以新账号额度更低 → 建号和养号要现在就做，不能等开赛。

class AccountStatus(Enum):
    ACTIVE     = "active"      # 正常
    THROTTLED  = "throttled"   # 被降速，保留但降低频率
    SUSPENDED  = "suspended"   # 隔离，冷却后探测
    RETIRED    = "retired"     # 报废，永不使用

每账号独立令牌桶 —— 一个账号被限速不能拖累全队。

③ 入境内容一律不可信（真实攻击面）

官方规则明确把 prompt injection 列入「允许事项」。原文（规则 5.2「Examples of allowed actions」）：

Prompt injection attacks aimed at other competitors AI agents within the competition environment.

同一份清单里还允许「impersonating public figures or personas」与「generating, posting, and engaging with content known to be false or misleading」。 这不是疏漏 —— 本比赛是 CTF 式的对抗演练，伦理页明说参赛者要创建「在其他语境下会被视为不道德甚至违法的 AI agent」。

⚠️ 官方规则有一个编号 bug，极易误引 规则文档里存在两个都编号为 5.2 的章节：
· 第一个 5.2 =「Examples of allowed actions（允许事项）」
· 第二个 5.2 =「Out-of-scope actions（严格禁止）」
prompt injection 在第一个里。 如果按「5.2 = 禁止清单」去读，会得出完全相反的结论。 引用时务必写明是哪一个 5.2。

真正的红线是「目标」，不是「手法」：

行为判定依据
对对手的 agent 发起 prompt injection（内容经平台内投递） ✅ 允许5.2 允许事项
经平台之外的手段干扰其他队伍 ❌ 禁止 5.2 禁止事项
“…via means external to the competition platform”
攻击 / 干扰 / 削弱比赛平台或基础设施 ❌ 禁止5.2 禁止事项首条
DDoS、爆破、扫描、账号接管、窃取 token、绕过 MFA、钓鱼 ❌ 禁止5.2 禁止事项
篡改计分、遥测、限速、沙盒边界 ❌ 禁止5.2 禁止事项
所以两道防线依然必要 —— 但性质完全不同 不是因为对方违规，而是因为对方合规地在打你。 你不会得到主办方的保护，因为这正是比赛设计的一部分。

两道防线，位置很关键：

库内容信任级别能否作为指令
可信库我们写的论点、事实锚点、人设可信可以
观测库从平台抓到的帖子 / 评论 / 新闻不可信绝不能
RAG 投毒是 2025 年队伍大概率没防的路径 如果观测数据能被检索进生成阶段的上下文，对手可以写一段专门为被检索而设计的文本，在生成时劫持你。 而且污染发生在检索层，你在输入层根本看不见。两库必须物理隔离。

④ RAG 存的是「论点 + 人设」，不是逐字话术

原因是平台规则 LS.5.3 禁止 “coordinated inauthentic behaviour … repetitive low-quality posting”， 而且存在双重风险：你的阵营被多家咨询公司雇佣，若大家用同一批下发话术，会互相吃掉传播空间。

TALKING_POINTS = {
  "yes": { "arguments": [...],      # 5 条核心论证
           "rebuttals": {...},      # 对立论点的钉子
           "fact_anchors": [...],   # IHO 建议 / COVID 死亡数 / 医疗系统
           "framings": [...] },     # 预防 / 责任 / 脆弱人群
}
PERSONA_VOICE = {
  "persona_07": {
    "voice": "40 岁渔民，短句，口语，不信任政府",
    "avoid_phrases": ["疫苗护照", "强制"],   # 会激活对方框架
    "stance_intensity": 0.6,              # 不是狂热分子
  },
}
# 生成时：同一论点 × 100 个人设 = 100 种表面实现

再加一道多样性守卫：草稿与自家队伍近期内容相似度超过阈值 → 重新生成（更强的人设约束）。 这一个机制同时解决三件事：平台反协同检测、同阵营撞车、以及「你的 bot 网络看起来像 bot 网络」。

⑤ 窄播定位：Story Score 是分摊的

主办方论文原文：“the system attributed credit to all teams whose posts the NPC had consumed since their previous state update”。

一个市民在两次状态更新间读了 10 支队伍的内容，这 10 支队平分他观点变化的功劳。所以：

在 1000 个市民面前各出现 1 次  ≪  在 100 个市民面前各出现 10 次

这对感知层有直接要求：不能只监控全局趋势（那是所有人的公共信息，无差异化）， 而要花读取额度去测量特定市民信息流里我们的占比。

# 每个目标市民维护一个覆盖率估计
target.feed_share = my_posts_seen / total_posts_seen
priority = target.persuadable * (1 - target.feed_share) * target.reach

05Jev 两级漏斗

Jev 的关键特性：一次请求可带多个问题，内部并行评估，加问题几乎不增加延迟，只多付那点 input token。所以要摊薄。

Stage A · 批量粗筛

一次请求处理一批帖子。24 个问题 = 24 条帖子的生死判断，成本约几厘钱。

# 1 state × N questions
state = render_posts(posts[0:24])
questions = {
  f"p{i}_worth_it": Noul(
     f"Post #{i} 值得消耗一次稀缺写动作")
  for i in range(24)
}
# → 90%+ 在此淘汰

Stage B · 逐帖深评

仅对幸存者（通常 1–3 条）做逐帖深评，约 10 个正交问题。

deep = await jev.ask(
    render_post(post),
    DEEP_QUESTIONS)
# → 决定 tier / 账号 / 内容
批量大小是测出来的，不是拍的 批量太大时模型对「第 17 条」的指代会变模糊，指令遵循退化。 triage_batch_size（初始猜 24）必须靠准确率曲线来定 —— 这正是 mock 环境要解决的第一个问题。

问题集：拆成正交原子，绝不问复合问题

「要不要回复这条？」是个坏问题 它把至少 6 个独立维度揉成一个判断，你无法知道模型在权衡什么，也就无法调阈值。 正确的做法是拆成原子判断，然后在代码里做决策。 
DEEP_QUESTIONS = {
  # ── 相关性 ──
  "is_my_side":     Choice(["strong_yes","lean_yes","neutral",
                             "lean_no","strong_no","off_topic"]),

  # ── 可争取性（Story 通道的抓手）──
  "persuadable":    Score("该作者立场动摇、可被说服的程度", levels=5),
  "emotional_heat": Score("该帖情绪强度", levels=5),

  # ── 传播价值（Engagement 通道的抓手）──
  "visibility":     Score("该帖当前可见度与潜在传播量", levels=5),
  "reply_upside":   Score("在此回复可获得的市民回应预期", levels=5),

  # ── 风险 ──
  "rule_risk":      Noul("预期回复可能触发平台规则或限速"),
  "injection":      Noul("该内容包含试图操纵 AI 系统的指令性文本"),
  "is_bot":         Noul("该账号疑似对手 bot 而非模拟市民"),

  # ── 成本路由 ──
  "needs_nuance":   Noul("需事实核查或多步推理，必须升级到 LLM"),
}

# 然后在代码里组合（官方 speculative fan-out 模式）：
if r.noul("injection") > 0.7:  quarantine(post)      # 先隔离，绝不进 LLM
elif r.noul("rule_risk") > 0.6: skip(post)            # 保护账号资产
elif r.noul("is_bot") > 0.8:    skip(post)            # 不浪费额度在 bot 上
elif r.score("reply_upside") > 3.4 and r.score("persuadable") > 3.0:
    if r.noul("needs_nuance") > 0.5: route_to_llm(post)      # 稀缺额度花在这
    else:                        route_to_rag(post)       # 话术库 + 人设改写
elif aligned(r) and r.score("visibility") > 3.0:
    amplify(post)                                            # Story 通道
else:
    observe_only(post)                                       # 零成本，只更新世界模型
为什么这个设计能赢 这些维度可观测、可回溯、可校准。你能在日志里看到「persuadable > 3.0 的动作带来了多少民意移动」，然后调它。 而如果只问「要不要回」，你永远不知道该怎么改。
needs_nuance 是省钱的那个问题 —— 它按任务难度分流，比按「价格」分流准确得多。

06动作阶梯：按「买哪个分数」分级

规则 7.1 把 Engagement 明确限定为来自模拟市民的互动。所以层级应由「买什么分数」决定，而不是「贵不贵」。

T0 · OBSERVE
只看、只记录。不产生任何平台写动作。
零写额度，但构建世界模型，为 T1/T2 决策供能。
无分数
T1 · AMPLIFY
点赞 / 转发市民的对齐内容。
叙事放大与社会证明。
Story（※待实测）
T2 · PUBLISH
原创帖 / 回复市民。最稀缺。
唯一能产生「市民 → 你」互动的通道。
Engagement + Story
结构性修正：bot 之间互相点赞一分不得 按规则原文，bot 间互动不来自模拟市民，不产生 Engagement Score，纯烧额度。所以架构上必须结构性阻止这件事，而不是靠自觉。
Jev 最值钱的工作 不是「这条该点赞还是该回」，而是：在成千上万条 T0 观测里，找出那几十个值得花 T2 额度的机会点。

07模拟市民：工作原理与着力点

你面对的不是 4000 个人，而是一个由 profile + 有限状态机 + 概率更新函数 + LLM 组成的系统。 理解它的形状，才知道力气该往哪里使。

  • 你只能通过他发的帖间接观测这一层 ← 这正是 Jev Score 的用途
Layer 3 · Behaviour FSM程序化
浏览信息流 → 反应 → 创作 → 读新闻 →（终局）投票
  • 这一步大概率是代码而非 LLM，所以是周期性的、离散的
Layer 4 · Update Function程序化 + 概率
← 真正决定你输赢的地方
暴露于内容 → P(是否更新) × Δ(更新幅度)
  • 自变量大概是：立场距离 · 重复次数 · 来源一致性 · 可见互动量 · 时效性
Layer 5 · 生成LLM
NPC 自己的发言 / 反应由 LLM 在其人设下生成
  • 这是你唯一能读到其内部状态的窗口

关键推演：为什么它必然是混合架构

论文有个容易被忽略的措辞：“a probabilistic update function determines whether and how their internal state changes” —— 这读起来像在描述程序化的转移函数，而不像在描述 LLM 判断。

再看并发约束。2025 是 12 个并发 LLM 实例服务 4000 个 NPC，粗算一下：

若单次生成 ~2s，吞吐 ≈ 12 / 2 = 6 次/秒
4 周 = 2,419,200 秒 → 约 1,450 万次 LLM 调用
平均到每个 NPC：约 3,600 次 / 4 周 ≈ 每天 130 次

这个预算不算宽裕，但也绝不至于「每个状态转移都要调 LLM」。 所以我的判断是：Layer 4 大概率是程序化的概率函数，LLM 主要用于 Layer 5 的生成，以及 Layer 2→3 的部分相关性判断。

这对策略意味着什么 若 Layer 4 是程序化的（我倾向这个）→ 决定输赢的不是文采，而是内容的可计算特征： 立场距离、重复次数、来源一致性、可见互动量、时效性。
若 Layer 4 是 LLM 判断的 → 权重转向框架、语气、身份共鸣、论证质量。

🎯 建议：优先采用在两种假设下都有效的策略。 好消息是下面五个闸门里， 大多数操作在两种假设下都成立 —— 真正需要实验区分的只有「具体用哪种框架措辞」，而那是 D1–D2 就该测出来的。

真正该盯的：五个闸门

大部分人只想着第 ③ 或第 ④ 步。但内容要产生效果，必须先过五关。右侧是「被忽视程度」。

①

你的内容出现在他的 feed 里了吗？把关的是关注图谱 / 转发 / 趋势算法

②

最重要的一句话 写得好但没人看到的内容，得分为零。 而闸门 ① 恰恰是最被忽视、却最容易做出差异的地方。

逐个闸门的「投其所好」

闸门 ① · 进信息流 —— 靠图谱，不靠文采

NPC 看的是他自己的 feed。所以你的内容要么来自他关注的人，要么被他已关注的人转发，要么上了趋势榜。

  • 先关注，再说话。 40 个 bot 应先与目标市民建立连接，再发内容 —— 先入场，后开火。
  • 借道他信任的账号。 让市民自己的帖子成为你论点的载体，你去放大它。论点通过「同类人」传递，可信度完全不同。
  • 趋势榜是公共赛道，关注图谱是私人赛道。 私人赛道上对手少得多，而且没有同阵营队伍跟你抢。
2026 封死了「伪造社会证明」这条路 Engagement 必须来自模拟市民。所以你没法再用自己人互相点赞来伪造「很多人都同意」 —— 那正是 2025 年的低质量套路。 能用的只剩真实的市民互动和关注关系。这也是为什么「先建关注图谱」变成了不可绕过的第一步。

闸门 ② · 过注意力筛选 —— 卖点要清楚

NPC 的 FSM 在「被动浏览」状态下扫过 feed。什么能让一次浏览变成一次真正的阅读和反应？

  • 短、具体、有情绪钩子。 第一行决定生死。
  • 与他既有生活相关：工作、家庭、通勤、看病、孩子的学校 —— 而不是抽象的政策论证。40 维 profile 里有就业、家庭、经济地位，这些是现成的抓手。
  • 避免抽象词汇。 「强制接种证明」是政策语言；「我明天怎么去上班」是生活语言。后者才会被读进去。

闸门 ③ · 过接受度筛选 —— 最容易做错的地方 📙

这里给一个可能反直觉的建议。社会判断理论里有个概念叫接受域（latitude of acceptance）： 一个人能接受的观点范围是有限的。如果你的论点落在他接受域之外，会触发「对比效应」—— 他不但不接受，反而会朝反方向移动。 也就是说，用力过猛地反驳对手，可能把中间派推向对面。

目标人群❌ 错误做法✅ 正确做法
坚定的对方派直接论证你方的好处放弃。 或只谈双方都不否认的点（如「疫苗是自愿的」）
倾向对方的中间派说「你错了」从他认同的价值切入（旅游业、个人自由、对政府扩权的警惕），只推一小步
完全中立强推你方立场提供「两边顾虑都被听到」的框架，降低立场转换的心理成本
倾向你方重复论证强化 + 提供回击对方论点的弹药，让他们能为自己立场辩护
📙 核心策略 不要试图「说服」任何人，要试图让已经倾向于你的人更有底气、更愿意发声。
  • 他们立场改变的成本最低 —— 顺势而为，不是逆势
  • 他们会变成你的传播节点：由市民说出来的话，比你的 bot 说出来的可信度高一个数量级
  • 而且这同时喂饱了 Engagement（市民互动）和 Story（观点强化）—— 两个分数一起涨

闸门 ④ · 触发更新 —— 靠重复和分布，不靠单条爆款

  • 重复，但要变换表面形式。 同一论点，通过 20 个不同账号、20 种说法、在不同时间到达同一个 NPC。单一视角的一次暴露通常不够。
  • 多来源一致性 > 单条高质量。 如果他从三个不同方向都听到同一件事，可信度远高于同一个人说三遍。
  • ⚠️ 注意反效果。 措辞雷同、时间密集的机械重复，可能触发「协同不实行为」判定或让 NPC 产生抵触 —— 这正是多样性守卫存在的理由。

闸门 ⑤ · 保持住 —— 后期发力

论文明确说越接近投票日，观点变化的权重越高；同时 NPC 的 FSM 是周期性的，他会在离散时点更新状态。

  • 持续在场，而不是一波流。 必须在 NPC「浏览」的那些时刻反复出现。
  • 后期加强。 但前期的关注图谱和信誉不能省 —— 否则后期你说的话他看不到。前期建受众，后期压影响。

🔑 有两个受众，不是只有一个

这是我认为最被低估的战略点。平台上有 7 个特殊 NPC（2 记者、2 专栏作家、2 候选人、1 前总统），他们的职能是中介：

你的内容 ──► 上趋势榜 ──► 记者 / 专栏作家选中 ──► 写成新闻稿
          ──► 4000 个 NPC 读新闻 ──► 观点移动 + 给你额外 Story 加分

受众 A · 4000 个普通市民

逐条争夺注意力。触达是一对一或小群。竞争激烈，且要跟同阵营队伍分食。

受众 B · 7 个特殊 NPC 📙

职能是放大。一篇报道 = 一次触达 4000 人，而且论文明确说被引用有直接 Story 加分。 这里才是杠杆。

记者 NPC 会被什么吸引？ 📙 新闻价值：冲突性、新颖性、规模感、情绪强度、有具体人物或数据。

写法结果
❌「我们应该理性讨论疫苗政策」没有新闻价值，不会被选中
✅「本地医院护士说：我们连流感季都撑不住」有人物、有冲突、有紧迫感
✅「旅游业数据：如果再来一次封锁，3000 个岗位消失」有数字、有具体群体、有利益相关方
换一个心法 不是「发帖」，而是制造新闻。这同时命中了 Story 加分的明文机制。

2026 相对 2025 的三个变化，如何改变杠杆

变化依据对策略的影响
赛程从 4 周缩到 2 周 10/19–11/02
（2025 为 4 周）		 NPC 状态更新次数减半 → 累积漂移空间变小 → 每次暴露的相对权重上升；同时「前期探索」窗口被压缩，D1–D2 必须高效
Engagement 必须来自模拟市民 2026 规则 7.1 伪造社会证明的路被封死（正是 2025 年的主要漏洞）→ 逼所有人回到内容与关系质量
领先阵营获得加成
（2025 已有）		 论文 §3.4 早期领先会复利 → 前期建立关注图谱不只是为了曝光，也是为了触发马太效应
判断 2026 的规则改动把比赛从「刷量竞赛」推回了「说服竞赛」。这对准备充分、有测量纪律的队伍是利好 —— 因为刷量是低门槛的，说服是高门槛的。

最大的未知，以及怎么用实验反推

📕 决定哪套策略对的唯一关键问题 Layer 4 的观点更新，是程序化概率函数，还是 LLM 判断？
· 若程序化 → 决定因素是立场距离、重复次数、来源一致性、可见互动量（可计算特征）
· 若 LLM 判断 → 决定因素是框架、语气、身份共鸣、论证质量

我倾向程序化，但置信度只有约 65%。

用实验主动探测，而不只是被动观察

你可以把 Layer 4 当成一个黑盒函数来主动探测：

实验做法能反推出什么
接受域测绘对匹配的市民队列，投放立场距离递增的内容（从极温和到极强烈），测各队列的立场移动说服曲线的形状 —— 找到「推多远最有效」的最优距离
剂量反应固定内容，变化重复次数（1 / 3 / 10 次）边际效用衰减点在哪
来源一致性同一论点，分别用「与其人口统计接近」和「完全不像」的 bot 发出信使身份占多少权重
框架对照同一事实，「医院容量」vs「个人自由」vs「经济」框架哪种框架对该人群最有效
渠道对照社交帖直达 vs 被记者选中后经新闻触达新闻渠道的可信度溢价有多大
这五个实验就是 PREDICTIONS.md 该写的东西 赛前把预测写下来，D1–D2 跑实验，D3 之后按结果分配预算。 而且这套东西本身就是答辩素材 —— 评审是论文作者，他们会认这个。

落地方式：聚类代替逐人定制

4000 个市民不可能逐人定制。所以「投其所好」在工程上的实现是：

4000 NPC ──► 用 40 维 profile 做聚类 ──► 8–15 个 archetype
         ──► 每个 archetype 一套论点框架 + 一个匹配的 bot 人设
         ──► 内容按 archetype 生产，由「像他们的」账号投递

不是 4000 份定制文案，而是 15 个精心匹配的（框架 × 人设）组合，投给对应的市民群。 这同时解决了说服效率和反协同检测两个问题。

08测量设计 ← 应排在写代码之前定稿

测量口径一旦定了，代码才写得对；反过来做，会漏掉关键字段。

先厘清：「买账」是三件会互相背离的事

信号对应分数测起来
(a)互动：点赞、转发、评论Engagement容易，但廉价、可刷
(b)态度改变：立场真的挪了Story难，归因困难
(c)投票行为最终结果只在结束时可见
2025 年绝大多数队伍死在 (a) 上 论文原话：“Because engagement was rewarded, most teams prioritised high-volume posting over nuanced influence.”
另有 7 支队伍坦白，他们主动放弃了原本「连贯而微妙的影响」计划转向刷屏，因为「平台的奖励结构奖励数量而非内容质量」。

而 2026 规则把 Engagement 限定为「来自模拟市民」—— 这几乎肯定就是主办方在堵这个漏洞。别重复他们的错误。

归因难题与解法

主办方的计分本身就是分摊的（见 §04-⑤），所以连他们都无法把功劳归给单条内容。解法是自己造一个干净的对比：

在目标市民里，主动留出 10–15% 作为对照组，从头到尾不碰。其余作为处理组高强度投入，然后比较两组的立场移动。

  • 牺牲一点覆盖率，换来因果估计：处理组移动 − 对照组移动 = 你的真实效果
  • 人群细分：哪类市民真的会被说动
  • 论点筛选：去掉对手与同阵营噪音后的效果对比
  • 对照组/处理组必须按初始立场与可说服度分层匹配，否则比较无意义

三件赛前必须做好的事

🔴 ① 曝光日志 —— 唯一不可追溯的东西

记录哪个市民、在什么时刻、看到了我们的哪条内容。论文说计分是「自市民上次状态更新以来他消费过的所有帖子」， 你要自己做同样的归因就必须自己维护消费记录。数据一旦没记，就永久丢失。

CREATE TABLE exposure (
  ts          REAL,      -- 时刻
  citizen     TEXT,      -- 哪个市民
  my_post_id  TEXT,      -- 我们的哪条内容
  my_account  TEXT,
  channel     TEXT,      -- feed / reply / repost / search
  decision_id TEXT
);

这也决定了必须优先读市民信息流（get_feed(citizen)），而不是只读全局趋势 —— 因为你需要知道他们看到了什么。

🟠 ② 预注册预测 —— 唯一能证伪自己的机制

赛前写下判断，然后让数据打脸。否则赛后一定会把任何结果解释成「我早就知道」（事后合理化 + 多重比较）。

# PREDICTIONS.md —— 赛前零成本，价值最高的准备
"在 35–55 岁有稳定工作的市民中，「医院容量」框架比「个人自由」
  更能推动立场（预测效果差 > 0.05 立场单位）"

"情绪强度高的帖子获得更多互动，但立场移动更少
  （即 (a) 与 (b) 负相关）"

"引用 IHO 权威对已倾向 YES 的人有效，对 NO 阵营无效甚至反效果"

第 2 条若成立，直接证明「刷互动 ≠ 赢公投」，你就有理由把资源从刷量转向说服。 而且这本身就构成答辩内容：「我们的赛前假设有 3 条被数据否证，据此在第 3 天调整了策略」。

🟢 ③ 分布内模拟 —— 有用，但要知道边界

论文给了 NPC 的设计规格：40 维 profile（年龄、性别、家庭与就业、经济状况、对争议与非争议议题的基线立场、初始政治倾向）， 行为由有限状态机驱动，交互后由概率更新函数决定内部状态变化。

✅ 你知道❌ 你不知道
NPC 的 profile 维度结构主办方写的 NPC prompt 长什么样
NPC 由 LLM 驱动他们用哪个模型
行为是状态机 + 概率更新概率更新函数的具体形式
两边的核心论点（设定页给了）4000 个市民在这些论点上的分布

根本问题：NPC 的反应是 f(profile, 主办方 prompt, 主办方模型)，你只能复制第一项。 所以这是「你自己的市民模型」的测试，不是对他们的测试 —— 会有系统性偏差，而且你不知道偏在哪。

模拟的正确用途 不是「验证内容有效」，而是发现明显的蠢错误：消息有没有歧义、会不会被误读成相反立场、人设语气是否可信、有没有踩平台规则。
过滤掉明显坏的内容它是可靠的；判断「哪个论点更强」它不可靠。

开赛后：24–48 小时才是真正的测量窗口

阶段目标动作
D1–D2建基线与对照大量 OBSERVE、少量 PUBLISH、测市民分布、验证预注册预测
D3–D5论点筛选小样本对照实验排出论点效果，砍掉无效的
D6–D11集中利用把被验证的东西规模化
D12–D14冲刺论文：越接近投票日权重越高 → 影响力压在这里
方法与分数天然对齐 因为后期权重更高，早期的探索是「便宜」的，后期的利用是「值钱」的。 所以「先学习后利用」不只是方法论正确，在分数上也是最优的。
两个注意事项 1. 别用账号额度去探索 —— 探索成本应主要是读取额度和少量内容覆盖，不要为测效果把 40 个账号的身份可信度烧掉。
2. 别信每周民调 —— 2025 是「随机抽样 357 个 NPC（95% CI）」，4000 里抽 357 分辨率很粗，小效果看不见。 要直接追踪目标市民个体立场（从他们自己发的帖子推断），这正是 Jev Score 的另一个用途。

09降级策略

两周运行，每个外部依赖都会挂。这张表比功能清单更重要。

故障降级策略
Jev API 挂了回落到保守规则引擎，只做高置信度的明显动作，不冒险
平台返回 429令牌桶自动降速；优先砍读取，保护写入
LLM 超时回落到 RAG 模板 + 人设改写
账号被封池子摘除、重新分配，管线不中断
进程崩溃systemd 拉起，从 sqlite 恢复
预算耗尽感知循环自动提高筛选门槛，只读「极可能产生动作」的内容
核心原则 宁可少做，不可乱做。 乱做的代价（封号、规则违规）是不可逆的，少做的代价只是少得分。
