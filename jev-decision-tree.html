00Where the two trees sit

Both trees are pure functions of the parsed JEV response. Neither one touches the platform, an account, or an LLM — they only decide, and record why.

validate input→ injection preflight
(offline, no network)→ pack→ JEV triage · 4 questions→ TREE 1→ JEV deep · 17 questions
conditional→ TREE 2→ handoff
execution_authorized=False
The one invariant Every handoff carries execution_authorized=False. A ready generation task supplies materials for the next module; it never authorises publication.

01Tree 1 · Routing — which evaluation path to take

RoutingPolicy.decide() · first match wins · evaluated top to bottom.

1
parsed.status == "failed"  or  error is not None  or  output is None
→ failed evaluation_failed
2
prompt_injection answer missing  or  not of type noul
→ review risk_unavailable  ·  missing risk is never treated as zero
3
prompt_injection  ≥ 0.5
→ review injection_signal  ·  threshold injection_review_threshold
4
relevance missing, wrong type, or not in {relevant, unrelated, unclear}
→ failed relevance_unavailable  ·  deliberately failed, not unrelated: a missing answer must not silently drop a post
5
relevance == "unclear"
→ deep relevance_unclear  ·  controlled by unclear_to_deep = true
6
relevance == "relevant"
→ deep relevant
7
P(unrelated)  ≥ 0.8
→ observe clearly_unrelated  ·  skips deep evaluation entirely · threshold unrelated_min_probability
8
otherwise — an unrelated label below the probability floor
→ deep weak_unrelated_signal
Note the ordering Risk is checked before relevance, so even a post that would be dropped as unrelated is still scanned for injection. Account level and engagement do not filter posts at this stage.

02Tree 2 · Action — like, reply, or do nothing

ActionPolicy.decide() · phase A runs first and short-circuits; only survivors reach the score comparisons.

Phase A · Guards (first match wins, no score is read yet)

A1
route == "review"  or  flow.status == "needs_review"
→ needs_review action=None assessment_requires_review
A2
flow.status ∈ {failed, deferred, needs_context}  or  route == "failed"
→ needs_assessment assessment_unavailable
A3
route == "observe"  and  flow.status == "observe"
→ decided action=no_interaction clearly_unrelated
A4
flow.status ∉ {evaluated, partial}  or  flow.deep is None
→ needs_assessment deep_assessment_required

Phase B · v2 delegation

B1
relative_stance ∈ {neutral, mixed}
→ needs_llm_assessment downstream_response_planning_required
No action and no account is selected. The downstream LLM chooses what, if anything, to answer. Neutral wording does not imply high persuadability.
B2
relative_stance is neither aligned nor opposing
→ pending_rules alignment_action_rules_pending

Phase C · Score gate

C1
answer missing  or  type ≠ score  or  legend ≠ exactly {0,1,2,3,4}
→ needs_assessment action_score_unavailable  ·  an unavailable score never falls back to a default
C2
aligned  →  read response_specificity   |   opposing  →  read reply_value
These are two different signals. response_specificity measures how clearly the response point is identifiable; reply_value is a separate opportunity rating.

Phase D · The thresholds

D-1 · aligned

1
response_specificity  > 2.5
→ decided · reply aligned_specificity_above_threshold · quality=ordinary
2
response_specificity  ≤ 2.5
→ decided · like aligned_specificity_not_above_threshold

D-2 · opposing

1
reply_value  < 1.0
→ decided · no_interaction opposing_value_below_threshold
2
reply_value  > 3.0
→ decided · reply opposing_high_account_required
required_account_level=high · minimum=high · reply_quality=high
3
1.0 ≤ reply_value ≤ 3.0  →  branch on the target's platform level
platform_level mapped tooutcome
highdecided · reply high / high / high
unknown (or unmapped)needs_account_metadata action=reply · opposing_target_level_unknown

A high-level target cannot rescue a skip The high-level upgrade is evaluated after the reply_value < 1.0 gate, so a high-profile target with a worthless reply opportunity is still skipped.

03Boundary semantics

Locked by tests/test_jev_actions.py, not by prose. These are the cases that silently break if a comparison flips between > and ≥.

Asymmetry worth remembering The aligned threshold uses > (2.5 → like), while the opposing lower bound uses an inclusive comparison (1 → reply). Scores are fractional, so neither boundary is theoretical.

05Defaults and known gaps

Two defaults decide whether Tree 2 actually acts. Both are deliberate, and both need external input.

settingdefaultconsequence
platform_levels {} Every opposing post in the ordinary interval returns needs_account_metadata instead of dispatching a reply. This path does nothing until real label mappings are supplied.
pending_rules ['engagement_trigger_thresholds'] Engagement has no standalone trigger. Visible likes and reposts can only inform reply_value qualitatively; they never override a decision on their own.
mixed_neutral_policy downstream_response_planning Neutral and mixed posts never inherit the opposing-post value thresholds — they are delegated.

Changing the thresholds

They are frozen dataclass fields, not literals scattered through the code:

from ctn.jev.routing import RoutingPolicy
from ctn.jev.actions import ActionPolicy

routing = RoutingPolicy(
    unrelated_min_probability=0.8,     # Tree 1 step 7
    injection_review_threshold=0.5,    # Tree 1 step 3
)
actions = ActionPolicy(
    aligned_reply_above=2.5,          # D-1
    opposing_reply_from=1.0,          # D-2 lower bound (inclusive)
    opposing_high_above=3.0,          # D-2 upper bound (strict)
    platform_levels=(( "<real label>", "high" ),),
)
Every change is traceable Both policies expose a fingerprint (sha256 of the canonical settings). Audit events record which fingerprint produced each decision, so you can answer afterwards: "which thresholds were live when that reply went out?"
What is not implemented Tree 2 decides what kind of interaction is warranted and what account level it needs. It does not choose an actual account, generate text, or publish. Those belong to the downstream account / LLM / review modules, which do not exist yet.
