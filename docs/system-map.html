CNT2026 系统地图

现在服务器上跑着的每一块：它干什么、属于哪一类、开局是什么状态、怎么关、出事看哪。点上面的方块跳到对应说明，点颜色标签可以只看某一类。

下文命令里的 ops 都是 docker compose exec fleet python -m ctn.ops 的简写，在服务器项目目录里执行。

10块地基。发帖、回复、举报、发送不丢不重，这些是骨架。
4块有用的。新闻、被隐藏提醒、自动降速、发布闸门里的口号检查。
6块猜测。复杂度主要在这里，第一天看数据决定留不留。
4块目前没有一键关闭的命令，要改策略文件或数据库，见页面底部。

每一块的说明

读帖 / 读评论 / 回读

地基每 1.5 秒读首页，每 2.5 秒读评论，每 5 秒回读互动数
干什么
把平台上的帖子和评论存进本地库，后面所有模块都靠它。读请求有配额，超了会自动等。
开关
不需要关。
出事看
ops status 里各 worker 的心跳时间；心跳停了说明进程卡住，先看 docker compose logs fleet --tail 200。

选帖打分

地基开
干什么
给每个新帖打分：新不新、热不热、是不是在回我们、作者像不像机器人。分高的先回。
开关
权重在 policies/reply-targeting-v1.json，改完要重启 fleet。
出事看
ops status 的 reply_reasons_24h：每条回复是因为什么被选中的。

按发帖频率判机器人

猜测开
干什么
一小时发 4 帖以上的作者当成 60% 像机器人，排到后面，少花 JEV。只影响先回谁，不会因此去举报。
为什么是猜测
假设市民 NPC 发帖不频繁。如果 NPC 本身就发得很勤，这条会把真市民排到后面。
开关
没有一键命令 只能改 policies/launch-v1.json 的 frequency_bot.min_posts 调大后重启。
第一天看
挑几个高频作者，看是不是认证 NPC。如果是，就关掉。

犹豫者加分

猜测开，权重 8
干什么
帖子里出现 "not sure / undecided / torn" 或以问号结尾，就优先回。
为什么是猜测
假设犹豫的人更容易被说服、也更算分。实际计分只看互动，不看对方改没改主意。
开关
没有一键命令 改 reply-targeting-v1.json 里 persuadable 为 0 后重启。

写回复

地基开
干什么
按账号人设、对方原帖、资料库和已核实的新闻写一条回复。
开关
单个账号停用：
ops account yes_0xx --mode standby
出事看
Discord 里的回复样本；内容不对劲先停这个号，再看 logs/。

发布闸门

地基开
干什么
发之前拦一道：AI 腔、和自己别的号措辞太像、重复口号、断言说过头。被拦的不发。
开关
不建议关。口号和过度断言的规则在 policies/news-v1.json。
出事看
如果回复量突然很低，看 ops status 里被拦的原因。

多号回同一帖

猜测开局关
干什么
热帖下面安排 2–3 个号接力回复，看起来像真讨论。
为什么是猜测
能多拿互动，但也是别家检测器最容易抓的"协同"信号。
开关
ops launch --batches on
ops launch --batches off
第一天看
别的队有没有大面积举报，我们的号有没有被隐藏。都没有再打开。

80 个人设 + 背景故事

地基yes.v2
干什么
每个号的年龄、职业、经历、关心的事、说话习惯。原创帖和回复都按这个写。
开关
ops persona standby --id P0xx
ops persona activate --id P0xx
还要做
账号绑定后在服务器跑一次 ops persona apply。

初始化第一帖

地基5 小时内随机分散，每帖间隔至少 90 秒
干什么
每个号的第一条帖子，是和政治无关的生活内容，之后才进入正常节奏。
开关
改分散时长（秒）：
ops launch --initialise-window 14400
出事看
ops status 里 initialise 的进度。

原创节奏

地基全队每日上限 10 / 16 / 24 / 32，18:00 后加速
干什么
macro-agent 容器按天数排期，给不同账号分配原创帖，失败最多重试 3 次。
开关
关掉排期：
ops campaign configure --originals-schedule off
改成固定上限：
ops campaign configure --daily-original-limit 12
出事看
ops campaign show

新闻层

有用开，每 10 分钟查一次新闻站
干什么
抓赛方新闻站的文章，抽出可以引用的事实，写回复时带"据某报道"。有冲突或被注入的文章会提醒。
开关
撤回一条事实：
ops news withdraw CLAIM_ID --reason "..."
没有整体关闭命令
出事看
ops news summary、Discord 新闻日报。

检测器 + 举报候选

地基开
干什么
根据 AI 腔、自曝身份、刷屏、成群互动等证据，给作者和帖子打"像机器人"的分，生成举报候选。
出事看
ops reports list

举报决策

地基未裁决总上限 40，同作者 2
干什么
算一条举报值不值：被判成立的概率 × 分数，减去判错的代价。
开关
上限在 .env：CTN_MAX_PENDING_REPORTS、CTN_MAX_PENDING_PER_AUTHOR（本地已改，服务器要同步）。
出事看
ops reports calibration

风险预算 / 停报代价

猜测预算 3.0
干什么
举报一旦被判"真人"，我们 6 小时内不能再举报那个帖子。这块估算停报会损失多少，同一时段多次停报只算一次。
为什么是猜测
依赖对裁判错误率（约 25%）和裁决速度的估计，开服前没有真实数据。
开关
ops reports automation --max-expected-genuine 5

shadow 开关

地基开：只记录决策，不真的举报
干什么
举报自动化的总闸。开着的时候系统只记下"本来会举报谁"，你看过觉得准再关。
开关
ops reports automation --shadow off
ops reports automation --shadow on
紧急全部暂停：
ops reports pause
建议
开服后看 2–3 小时的候选。误报基本都是 AI 腔、自曝身份这类没争议的，就关掉。

发送恢复 + 安全停机

地基自动
干什么
发出去没收到回应的帖子，在 1/3/8/14 分钟查一次，确认没发出去才重发，不会重复发。重启前先把正在发的请求等完。
开关
不需要。重启照常用 git pull 后 docker compose up -d --build，runbook 里有步骤。
出事看
Discord 的 unknown 提醒。

每号每日上限

地基开
干什么
限制每个号每天发多少，防止单号刷屏被盯上。
开关
在 reply-targeting-v1.json 的 caps。

被隐藏 → 自动降速

有用2 帖被隐藏 → 每天最多 8 条
干什么
3 帖被永久隐藏就封号，所以第 2 帖被隐藏时先给这个号降速。
开关
解除单个号：
ops launch --unslow yes_0xx
没有整体关闭命令

回读自己的帖子

有用每 10 分钟，最近 48 小时
干什么
检查我们的帖子还在不在。显示被隐藏，或连续两次读不到，就算被隐藏，发提醒。
出事看
Discord 的 own_post_hidden 提醒。

自查评分

猜测每 30 分钟，只提醒，不自动处理
干什么
用别家检测器可能用的标准扫我们自己：AI 腔、号之间措辞雷同、几个号扎堆进同一帖、发帖过多。
为什么是猜测
我们并不知道别家检测器看什么。不过它只发提醒，猜错了也没有副作用。
出事看
ops status 的 self_check。

Discord 提醒 / 审核

地基开
干什么
所有提醒都汇总到这里：发送异常、被隐藏、降速、新闻冲突、自查、举报待审。
出事看
提醒发不出来：docker compose logs discord-review。

开局最简配置

  1. 初始化帖、原创节奏、单号回复：开
  2. 多号回同一帖：关（已是默认）
  3. 举报：shadow 开着，只看不报（已是默认）
  4. 服务器 .env 同步 40 / 2
  5. 其余猜测类模块先不动，它们只影响排序或者只发提醒

第一天只看这几个数

  1. 我们的帖子有没有被隐藏：Discord 提醒
  2. 市民有没有点赞、回复、关注我们：ops performance
  3. 举报候选准不准：ops reports list
  4. 别的队在干什么：刷屏多少、有没有成群互动
  5. 高频作者是不是认证 NPC：决定频率判机器人留不留

目前没有一键关闭命令的 4 块

  • 按发帖频率判机器人：改 launch-v1.json 后重启
  • 犹豫者加分：改 reply-targeting-v1.json 后重启
  • 新闻层整体：只能逐条撤回事实，worker 本身一直在跑
  • 自动降速整体：只能逐个号解除

四块都不危险：前两块只影响先回谁，新闻层有逐条撤回，降速只会让号发得更少。真要关，改文件后重启就行，大约 1 分钟。
