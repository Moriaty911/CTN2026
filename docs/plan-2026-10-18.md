## 0. 摘要

当前代码的安全层和状态层已经比较完整，但**开赛前真正会阻塞运行的不是 SQLite，而是**：

1. 没有显式 `CTN_SIDE`，服务可能 observe-only；
2. 账号池、warmup、被 ban 后替换没有闭环；
3. Blue 在没有裁决读取 API 时无法闭环；
4. 回帖的 1200 字符配置与 280 字符 postflight 冲突；
5. 语料库质量不错，但尚未接入运行时，且不能直接丢进旧 `ctn.ops background`；
6. Pi cron 不存在，原创发帖没有 Python 兜底；
7. 回帖材料固定用第一条 background，语料多了会乱配。

本计划按四个阶段执行：

| 阶段 | 时间 | 目标 |
|---|---|---|
| P0 | 今天到开赛前 | 能安全 live：阵营、账号、warmup、语料、Blue 手动模式、云部署 |
| P1 | 开赛后 0–72 小时 | 修掉直接导致丢回复、烧钱、卡死的问题 |
| P2 | 第一周 | SQLite 长跑、举报闭环、检索、监控 |
| P3 | 比赛期间 | 计分、民调、动作实验、校准 |

**总原则：**

- 开赛前不做大重构；只做可回滚、可验证的修复。
- 每个改动单独开关、单独测试、单独回滚。
- 不在 live 期间做破坏性 schema 迁移。
- 不伪造裁决源、不伪造事实、不把新闻/VIP 当 verified fact。
- SQLite 继续作为 source of truth；**不引入 Meilisearch**，先用静态 JSON / SQLite FTS5。

## 4. P0：开赛前必须完成

### P0-01 配置与启动

**问题：** `.env`/`.env.example` 没有 `CTN_SIDE`，Docker 命令没有 `--side`，默认 dry-run；服务可能 observe-only。

**改动：**

- `.env` / `.env.example` 增加 `CTN_SIDE=yes`。
- Docker/启动命令显式 side，或启动时强制读取。
- live 启动 fail-fast：
  - side 为空 → 拒绝 live；
  - side 与 catalog 不一致 → 拒绝；
  - 没有 active 账号 → 拒绝；
  - JEV/LLM/平台凭证缺失 → 拒绝。
- 心跳反映真实：mode、side、active accounts、high accounts、report mode。
- 默认 dry-run 保留，但 live 不能静默降级。

**涉及：** `ctn/main.py`、`ctn/config.py`、`.env.example`、`docker-compose.yml`。

**验收：**

- `ctn.ops preflight` 无 blocking；
- 没有 `CTN_SIDE` 时 live 启动失败；
- 心跳可看出 side 和账号数。

### P0-03 Warmup

**现状：** `ctn.macro warmup` 单账号已有；每个 persona 2 条 daily seed；没有批量/调度；全队每日 10 条原创限制也适用于 warmup。

**改动：**

- 新增 `daily_warmup_limit=15`，与战略原创 10 分开。
- `claim_action` 对 `purpose=warmup` 使用 warmup 计数器。
- 批量/定时 warmup：
  - 选择 active、24h 内未发原创、当日 warmup 额度未满的账号；
  - 从 `daily` examples 取一条；
  - 走 `StrategicPublisher.publish(purpose="warmup")`；
  - 仍过 JEV/长度/查重/账号锁/每日额度。
- Python warmup-only worker：
  - 不依赖 cron；
  - 只发 warmup，不做战略原创；
  - Pi cron 可用时关闭，避免重复。
- `harness.md` 人类指令从“全队 under 10”改成“战略原创 under 10；warmup 单独 15”。

**默认节奏：**

```text
Day 0: 10 条 warmup
Day 1: 15 条
Day 2: 15 条
Day 3: 10 条
合计 50 条 → 50 个 active 账号各 1 条
```

**涉及：** `ctn/macro/publisher.py`、`ctn/persona/warmup_seeds.py`、`ctn/storage/runtime.py`、`ctn/main.py`、`harness.md`。

**验收：**

- 第一天能按计划发 10–20 条；
- 账号 24h 原创锁生效；
- 没有重复 seed；
- Pi 与 Python 同时运行不会重复发。

### P0-05 Blue track：手动裁决模式

**现状：** SDK 只有提交举报的 API，没有裁决读取 API；生产装配 `UnavailableModerationSource`，自动举报 0 提交。

**改动：**

- 新增 `CTN_REPORT_MODE=off/manual/auto`：
  - `off`：不提交；
  - `manual`：允许提交，裁决靠导入；
  - `auto`：只有真实读取源验证后才启用。
- 解耦 `event_source.available`：manual 下允许提交，不要求 source available。
- 举报 detail 本地校验：
  - 帖子：`I think that this content is inauthentic (bot) activity because...`
  - 账号：`I think that this account is conducting inauthentic (bot) activity because...`
  - 空 detail/错误前缀：本地拒绝，不发 HTTP，避免 400 占用 3/分钟。
- 使用 `ACCOUNT_REPORT_REASONS`；账号举报只允许固定词表。
- 账号举报支持重报：
  - `account_reports` 历史化/upsert；
  - `action_key` 带 report attempt；
  - `moderation_events` 按 report 去重；
  - dismissed 后可再次举报。
- 100 动作来源：
  - 有 API/平台字段则接入；
  - 没有则 `ctn.ops account-activity` 手工导入；
  - 不拿帖子数冒充动作数。
- 400/403/429 本地退避：
  - 400 → 标记格式/目标不可重试；
  - 403 → 停报/账号退避；
  - 429 → Retry-After。
- 裁决导入：
  - 现有 `ctn.ops import-events`；
  - 或文件源，每日导入。
- 明天问主办方：
  - `report_post`/`report_account` 响应是否含 `outcome`；
  - 有没有 activity log/CSV/裁决 API；
  - 账号举报是立即还是 24h。

**默认：**

```text
Blue = manual
max_pending_reports = 5
前 3 条人工 review
每天导入一次裁决
账号举报暂缓
```

**涉及：** `ctn/moderation/reporter.py`、`ctn/moderation/events.py`、`ctn/client/legit_v1.py`、`ctn/storage/runtime.py`、`ctn/actuator.py`。

**验收：**

- 手动模式能提交 1 条举报并写 pending；
- 导入 upheld/rejected/dismissed 都能更新；
- dismissed 后可以再报；
- 空 detail/错误 reason 不发 HTTP；
- 400/403 不会每 10 秒重撞。

## 6. 回帖正确性与产能（P1：0–72 小时）

| ID | 问题 | 改动 | 验收 |
|---|---|---|---|
| REP-01 | 生产 1200 vs postflight 280 | `DraftOptions(max_reply_chars=280)` 或配置 280；生成/校验共用 | 281 在生成阶段拒绝 |
| REP-02 | 重试无上限/错误分类 | transient/semantic/terminal；attempts 退避 + 最大次数；postflight transport 归 transient | 超时不会永久 skip；语义拒绝不反复 |
| REP-03 | 回复批次目标粘滞 | `(target_id,target_version)` 或状态判断；cancelled 后可新 batch；enqueue 不因旧 batch 跳过 | 取消→编辑→新 batch |
| REP-04 | 评论空页死循环 | 空页 + `next_cursor=None` 清 cursor/标 done；有 cursor 推进 | 不重复请求同一空页 |
| REP-05 | 检测器一词规避 | `_unquoted` 不再因整篇 said/example 关闭检测；局部豁免 | “As an AI ... said” 仍触发 |
| REP-06 | confirmed bot 被评估 | `process_pending` 跳过 confirmed_bot；开关 | 不消耗 JEV/LLM |
| REP-07 | worker/Auth/事件异常 | worker try/except；consume_events 逐事件；AuthError 账号级隔离 | 注入异常服务仍活 |
| REP-08 | 重复回复文本 | FLAG 至少 BLOCK/needs_review；查 SQLite normalized text；跨账号 | 第二次相同文本被拒 |
| REP-09 | FIFO 无优先级 | 加 ranked trending；post_tasks priority；按 JEV score/engagement | 高价值先执行 |
| REP-10 | JEV/LLM 成本无预算 | 每日/每小时上限；cheap prefilter；超预算保留队列 | 成本可观测、可停止 |
| REP-11 | 指标/等级/语言 | 缺失 metrics 不写 0；author unknown 不默认 standard；英文检查不只非拉丁 | 语义正确 |
| REP-12 | P04/P05/P06/P09 未支持 | 先明确 unsupported；或后续扩展 | 不静默浪费 |
| REP-13 | 日志含正文 | `decisions.jsonl`/`actions.jsonl` 改 metadata-only 或更新文档 | 与文档一致 |

## 7. Blue 举报完整计划

### BLUE-01 模式

- `CTN_REPORT_MODE=off/manual/auto`。
- `manual` 允许提交，裁决靠导入。
- `auto` 需要真实读取源。

### BLUE-02 本地格式校验

- 帖子/账号 detail 前缀；
- `POST_REPORT_REASONS` / `ACCOUNT_REPORT_REASONS`；
- 空 detail/错误 reason 不发 HTTP；
- 400 不退化成重试。

### BLUE-03 账号举报

- `account_reports` 历史化/upsert；
- `action_key` 带 report attempt；
- `moderation_events` 按 report 去重；
- dismissed 可重报；
- 100 动作来源（API 或手工导入）。

### BLUE-04 事件消费

- `consume_events` 逐事件 try/except；
- 无效/早于提交/对象不存在 → 记录并继续；
- 重复事件幂等；
- 不因一条坏事件退出服务。

### BLUE-05 退避

- 400：格式/目标不可重试；
- 403：停报/账号退避；
- 429：Retry-After；
- 6 小时停报本地可识别（导入或 403 推断，需谨慎）。

### BLUE-06 待审与人工

- `max_pending_reports=5`；
- 前 3 条人工复核；
- 账号举报暂缓，直到 100 动作 + 1 条 hidden post；
- 每天导入裁决。

### BLUE-07 主办方问题

- 裁决 API/activity log/CSV；
- report response 是否含 outcome；
- 账号举报即时还是 24h；
- report_id 与裁决对应关系；
- 6 小时停报如何观察。

## 17. 附：语料评估摘要

### 优点

- 四类材料分层；
- facts 保留限定词/归属；
- argument 有 fair_objection/response_boundary；
- unknowns 有 do_not_infer/safe_response；
- 50 段原文有哈希/审阅；
- 33 个验收题；
- 校验脚本通过。

### 待修

- 没有 P02 style examples；
- P08 style 与 argument purposes 不一致；
- F016/U007 未被 argument 引用；
- F014 较笼统；
- 只有 YES，没有 NO 系统语料；
- 没有两报纸/VIP；
- 没有运行时接入；
- style 是完整帖子，有复制风险。

### 接入原则

- facts → JEV `verified_background` + MaterialBrief support；
- arguments → LLM 论证，不当事实；
- unknowns → LLM 约束/P08 gap；
- styles → 声音，最多 1 条，不复制；
- raw_review → 不运行时；
- review cases → 检索验收。
