# YES RAG v1.1 静态基础语料

当前版本为 `yes.rag.v1.1`，整理日期为2026-10-18。静态检索、JEV前置材料、Pi查询、冻结快照及生成审核已接入代码；两报纸／VIP持续采集仍未接入。运行与验证说明见[实施手册](../implementation-2026-10-18/runbook.md)。离线语料校验脚本只报告元数据质量，不证明实际模型效果。

先读[完整审阅预览](preview.md)。当前正式来源是 [yes.v1.1.json](../../config/rag/yes.v1.1.json)，预览由脚本生成，不维护第二套正文。英文正文供后续模型使用，中文标题和处理理由供人工审阅。原 [yes.v1.json](../../config/rag/yes.v1.json) 与原验收题保留不变，供历史回放。

这是一份“官方 setting＋用户原文＋编辑补充”的静态基础库。sources 仍只有 official_setting、user_raw、editorial 三类；报纸背景仅来自官方设定，没有新闻条目、VIP 帖子或持续更新能力。

## 四类材料

| 集合 | 数量 | ID | 用途与边界 |
|---|---:|---|---|
| `facts` | 32 | F001–F032 | 官方虚构设定中的事实、有限证据或有明确归属的立场。保留来源章节、日期、限定词；不是实时监测或独立医学验证。 |
| `argument_cards` | 21 | A001–A021 | 支持 YES 的政策判断和推理。每张卡关联事实与未知项，列出合理质疑和回答边界；不能证明政策必然有效。 |
| `style_examples` | 30 | S001–S030 | 口语表达、直接回答与聚焦提问示例，最长 182 字符。不是可直接复制发布的答案，也不赋予人物家事、临床经历或专业权限。 |
| `unknowns` | 22 | U001–U022 | 未说明、证据有限、需要更新或不属于共享事实的事项。含不可推断内容及可用答法；没有说明不等于不存在。 |

YES 的核心始终是支持公共空间准入的接种证明要求。承认负担、讨论实施细节和提出保障措施，不自动变成 NO；另一方面，不能用泛泛支持疫苗替代对准入要求的明确立场。

## 来源和处理原则

- [官方设定](https://capturethenarrative.com/info/competitions/2026/setting/)是虚构世界的基线来源；F 系列每条记录有来源 ID 和原章节。`required_qualifiers` 是与正文一起保留的语义约束。
- `reported_position` 表示可确认某组织提出了主张，不表示其预测已经实现。不能去掉归属，再把预测改成事实。
- `source_snapshot` 表示来源快照。描述比赛进行中的现状必须另有带日期的更新，不能把基线当实时数据。
- [原始 MD](../../vote_for_raw_rag.md)完整保留，SHA-256 写入来源记录。原文没有升级为事实来源。
- 新增论证、问题和示例属于编辑性补充，不是外部研究。没有引入真实国家法律、真实疫情统计或虚构的新政策细则。
- 官方来源也经过筛选：无关选举数据中的不一致没有导入，不能用来推断当前公投支持率。

每张论点卡包含主张、推理、适用主题/目的、关联事实、未知项、可能遇到的合理质疑、不可越过的边界以及原文线索。质疑是参考视角，不是必答题；回复仍以目标帖和必要父帖的实际内容为准。价值判断可以清楚表达，但必须与经验性结论分开。

## v1.1 修订内容

- 新增 S026–S030 五条 P02 专用示例，分别直接解释 YES、说明试验证据、保留传播效果限定、承认费用未知、区分豁免未说明与豁免不存在。每条均列出依赖的事实或未知项；它们仍是风格参考，不能替代实际核准依据。
- F016 接入 A003，增加 C034 检查“多数已知病例较轻”不等于没有严重后果，也不能单凭这一事实证明准入政策合理或不合理。U007 接入 A011，保持医学保护时间、剂次要求和证明有效期的区别。F016 没有混入 COVID 历史卡 A019。
- F014 在同一经济背景主题内补充具体内容；F018–F027 新增疫苗平台、医疗资源、COVID 历史规模、人口、外岛交通、两报纸背景和政治程序。新 H2D2 疫苗改造的是已有 mRNA 平台；新疫苗不等于全新平台，更不等于已排除所有风险。
- F028–F032 系统整理 NO/KITB 的自主权、日常准入、旅游信心、比例性和未来权力担忧，均为 `reported_position`。事实是对方提出了这些主张，不是预测已经成立。相关 YES 卡引用它们以理解和回应实际论点，不改变阵营。
- 现有 P05 底层契约没有因此变成自动回帖能力。政策意见分歧也不能直接作为可比的事实冲突。

## 风格示例的用途和接入边界

| 用途 | 示例数 |
|---|---:|
| P01 / P03 / P07 | 各 21 |
| P02 | 5 |
| P08 | 4 |

用途以 style 自身的 `purposes` 为准。`argument_id` 仅提供主题上下文，不继承、限制或扩大用途权限；不能按关联 argument 的用途过滤掉 S021–S024，也不能把关联论点全文作为 P08 的论证输出。新验收题明确保存目的与预期示例 ID，离线校验检查这种元数据关系；实际检索过滤还没有实现。

后续每条生成最多提供一条示例，可以不提供。persona 声音优先；提示词须明确 `voice reference only; do not copy wording or use its claims as evidence`。近抄检查应考虑整体近似和较长片段复用，并避免因共有短语误杀；触发后复用现有的一次定向重写预算，仍不通过则取消。相似度检查、阈值校准和运行时数量限制均属于后续接入要求，目前没有实现。

## 原始 50 段如何使用

| 处理方式 | 段数 | 含义 |
|---|---:|---|
| 保留为论点 | 1 | R010：保留工作人员利益的规范性表达，不将“值得保护”解读为效果保证。 |
| 改写并合并 | 30 | 保留可用核心，删除绝对化、未经确认的条件或动机判断，合并重复内容。 |
| 仅保留主题 | 18 | 具体经历、类比或临床结论不能采用；只保留其关切的问题。 |
| 排除 | 1 | R032：猜测反对者从未照护过脆弱亲属，缺乏依据，也没有独立回应价值。 |

逐段处理记录在 JSON 的 `raw_review` 及预览中，包括原始行号、段落摘要哈希、长度、处理理由和输出 ID。它是审阅记录，不属于第五类检索语料。

两处特别保留了原意：R006 的年龄门槛是原作者提出的规则，不是官方已公布规则；R043 的未来加强针意愿是条件性表态，不是声称现在已存在加强针制度。两者仍不作为官方事实导入。

## 补齐的薄弱部分

本版增加或强化了隐私与核验、实施成本、不能履行与拒绝履行的区别、就医与基本生活、工作和学校安排、外岛和无障碍、问责与申诉、期限与复审、访客证明、政策增量效果，以及反对准入不等于反对接种的准确表达。

这些主题中尚无已确认答案的部分，进入未知项和提案边界。不会因为需要一句有说服力的话，就宣称已经有免费接种、医疗豁免、远程上课、个人数据不保存、自动到期或其他保障。

人物的固定经历仍以现有 persona JSON 为准。语料没有给任何账号增加家属病史、个人接种史或“亲眼见过所有患者”的经历。职业标签不能证实医学判断，也不能授予平台能力等级。

## 校验与更新

从仓库根目录运行，仅需 Python 标准库：

```bash
python3 scripts/check_rag_corpus.py
# 修改正式 JSON 后重新生成预览：
python3 scripts/check_rag_corpus.py --write-preview
```

[corpus.schema.json](../../config/rag/corpus.schema.json)定义严格交换格式；本地脚本实现该文件实际使用的 JSON Schema 关键词子集，遇到不支持的关键词会报错，不宣称实现完整 JSON Schema 规范。

检查包括字段/类型、多余字段、ID 与引用、英文正文、事实来源类别、限定词保留、来源日期、原文文件与逐段哈希、50 段完整覆盖、双向溯源、示例去重及长度、预览一致性和验收题引用。结构校验不能替代逐条事实审阅，也不能测出说服效果。

[review-cases.v1.1.json](../../config/rag/review-cases.v1.1.json)提供 52 个后续检索/生成验收问题，覆盖全部 22 类未知事项和 32 条事实/归属主张，标注预期材料、部分用途/示例关联和禁止越过的边界。本批检查题库引用及用途元数据有效，尚未运行检索召回或模型回答测试。

`coverage_requirements` 让本次发现的 P02 缺失、F016 论点/题库漏用和 U007 论点漏用成为明确的校验失败。报告同时列出未被论点引用的材料供人工审阅，不强制所有背景都挂上论点。目前 F021 人口、F023/F024 报纸背景、F027 总统表态作为可直接查询的背景保留，各有验收题。

更新时修改正式 JSON，保持旧 ID 的含义不变；事实变化应增加语料版本并保留历史，不能悄悄加强原结论。若原始 MD 变化，校验会失败，必须重新审阅变动段落并更新来源哈希和逐段记录。

## 后续接入要求

当前不能直接把 `yes.v1.1.json` 交给旧的 `ctn.ops background`：两者契约不同，而且该导入方式无法保留四类材料的用途边界。

后续索引应明确区分四类材料。`raw_review`、原文摘录、排除理由及禁止断言的示例不应作为正向答案正文检索；`do_not_infer` 是约束元数据，必须保持否定语义。检索命中后应按类型打包，而不是把整个 JSON 拼进系统指令。

需要依次完成检索、相关依据选择、版本化快照、主回复/追加回复/原创审核传递，并让 Pi 与 Python 共用查询接口。不得改变既有 0—4 分动作规则、0.90 多人门槛或账号权限；多人回复仍需有真实互补内容，不能因为检索到了更多表达示例就追加回复。

本批校验脚本不会导入运行模块、打开状态库、调用外部模型或提交平台动作。

语料JSON中的`status`保留整理阶段的历史标记。离线校验器不检测部署状态，相关能力返回null表示未检查；当前接入能力以`ctn.ops preflight`及运行回归测试为准。
