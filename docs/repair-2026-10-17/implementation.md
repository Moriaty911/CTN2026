## 关键状态与恢复

- 动作在网络调用前写入，状态为 claimed → sending → succeeded / failed / unknown；排队阶段由持久化处理任务表示。账号与目标在发送前占位。
- 机会有效 30 分钟，草稿有效 5 分钟。等待 HTTP 额度、登录或服务端冷却后，还会在真正发送前检查期限、目标版本、账号状态及额度。
- 发送中失去持有者恢复为 unknown；领取后尚未发送则可重试。unknown 不自动释放账号保护或对目标再次发送。
- 成功发布、账号计数、冷却、互动记录及举报 pending 账本在短事务内完成。网络与模型调用不持有 SQLite 写事务。
- 真实请求与预约分开记录；预约取消不会消耗实际请求计数。最终发送闸门也在数据库中，防止 Retry-After 结束时多个等待者一起发送。

## 举报模型的边界

版本文件为 policies/evidence-v1.json。初始规则是至少 85 分并有两种实质证据组；这不是 85% 准确率。官方约四分之一错误裁决没有被解释为独立同分布噪声，也没有把本地积分代入机器人概率公式。

帖子举报和账号举报都有执行路径。账号路径需要至少一条已确认的永久隐藏帖子，以及有来源和采集时间的至少 100 次账号动作；未确认的公开字段不会被猜测为动作总量。裁决去重、跨日统计、驳回停报与反馈均独立于身份认证。

还未证明这些初始权重、账号分工、目的选择和稿件能够提高比赛收益。测试覆盖的是执行一致性、边界与恢复；实际识别准确率、内容质量和收益需要后续影子运行及真实数据校准。

## 验证与测试变更

原有 490 个 unittest 场景全部纳入回归。新增 32 个故障和一致性场景；另将原先未被 unittest discover 收集的 11 个函数测试接入，因此当前总数为 **533**。完整环境、回归、容器与性能结果见 [验证记录](validation.md)。

旧断言的修改依据：

1. dry-run 的 ok=true 改为 status=simulated、ok=false；验证正式计数保持不变。
2. think 不再提前记“已发送”；只有 Actuator 确认成功才记账，测试通过实际执行验证冷却。
3. 单条 AI/模板/外语/提问/口号不再确认机器人；改为验证各组分数、封顶和不传播身份。
4. 同步连续提交三条并立即成立，改为一次待审与三个独立裁决事件；驳回不会变成 verified NPC。
5. 固定每日十条囤积，改为待审上限、裁决释放额度和明确团队的递减排序。
6. 回复材料夹具显式提供合成可信参考；另有无证据时禁止生成事实回答的反向测试。
7. JSON 状态夹具改为 SQLite；重复评论结束分页改为继续读取服务端游标。

运行与恢复见 [操作说明](operations.md)，策略执行路径见 [三棵逻辑树](logic-trees.md)。

## 仍需真实平台验证的启用门槛

正式服务装配 UnavailableModerationSource；没有虚构的裁决端点。10 月 19 日需要确认真实来源、认证、事件 ID、时间与分页，并以真实响应补充契约测试；通过影子运行后才启用对应自动举报。404、帖子不见或暂时隐藏均不能当裁决。

应同时核实账号动作总数来源、真实比赛结束时间、平台实际路由限制和请求预算。当前限速是保守本地配置与官方 SDK 的服务端反馈结合，不宣称已在比赛负载下验证。
